Additional vectors in `test/python-vectors.json` were generated by executing the upstream `crypto.py` with deterministic synthetic inputs using Python's standard library.

## Preserved behavior

- Eight-digit SHA-1 TOTP with a 30-second interval.
- Restore-code alphabet, digest derivation, and HMAC challenge response.
- Exact RSA public parameters, unpadded RSA, and minimal-length big-endian ciphertext.
- Enrollment message fields, one-time pads, endpoint paths, regional hosts, and HTTP transport.
- INI configuration sections and secret formats, default selection, and legacy hex migration.
- CLI command names, plus `bna SERIAL` shorthand documented in the upstream README.
- Undashed output from `prettifySerial`, as implemented and tested upstream.

## Intentional differences

- Idiomatic camelCase names; no snake_case aliases. Network calls return promises.
- Enrollment returns `{ serial, secret }`, and binary operations return buffers.
- TOTP and Base32 are implemented using Node built-ins, removing external dependencies.
- Restore-code derivation normalizes serial inputs. Malformed Base32, serials, restore codes, and unexpected response lengths fail explicitly.
- Duplicate restoration is checked after serial normalization, preventing accidental replacement through differently formatted input.
- Writes use an atomic rename and restrictive POSIX permissions. Read-only operations do not create missing directories.
- The INI reader covers python-bna's generated configuration format, comments, and default secrets. It does not implement arbitrary ConfigParser interpolation or multiline values. Comments are discarded on writes.
- Requests have bounded duration and response size. Server status 600 retains the original invalid-restore-key message.
- `new` preserves the Python implementation's default of selecting the newly enrolled serial, even though its README describes a different default.

Current operation of Blizzard's legacy service is outside the verified compatibility claim. Legacy enrollment and restoration are tested against local protocol fixtures; live legacy time and enrollment requests returned HTTP 502 on 2026-09-18.

## New browser-assisted enrollment

The `enroll` command, browser login receiver, and `ModernAPIClient` are additions to the Python port. They follow the mobile SSO exchange and JSON enrollment flow described in [upstream issue #42](https://github.com/jleclanche/python-bna/issues/42). This is a community-documented flow, not a claim of an officially supported third-party enrollment API.

One real account attachment succeeded on 2026-09-18. The observed login redirect stayed on an account.battle.net path ending in `/localhost` and displayed a 404 while still supplying an `ST` token. The parser accepts that observed address as well as loopback redirects.

The newer response's restore code is saved with its secret. `show-restore-code` prefers that saved value and falls back to the original derivation for older configs. Recovery JSON is retained separately before the validated values are committed to the INI file.
